GREYMEMORY · SELF-HOSTED MEMORY FOR AI AGENTS

Memory that knows when facts change.

greymemory is a self-hosted memory layer for AI agents like Claude Code, OpenCode, or your own. It extracts atomic memories from conversations, detects contradictions, supersedes stale facts while keeping their full history, and serves the current truth through hybrid BM25 + vector search — all on SQLite, with any LLM and embedder you bring. No cloud dependency, no API lock-in, no data leaving your server.

This page is a live, interactive knowledge-graph console rendered over a real LongMemEval ingestion (the full benchmark run spans 25,000+ extracted memories across 86 users; the hosted demo serves four of them live). Open it in a browser to explore the force-directed graph: hover a node to read the memory, click one to light its neighborhood (seed → EXTENDS expansion → supersession chain), and scrub time to see answers change as facts get superseded and expire.

The problem, measured

Long-term memory for AI is unsolved. On LongMemEval, GPT-4o scores 91.8% reading a chat history offline, but ChatGPT's own long-term memory scores 57.7% on the same questions and Coze scores 33.0%. Even handing GPT-4o the whole transcript in its context window, it loses a third of its accuracy to surrounding noise: 87.0% → 60.6% (the "lost in the middle" effect — bigger context windows make it worse, not better). Having the information isn't using it. The paper distills what a memory must actually do into five abilities:

  • Information Extraction — recall one specific detail from months of conversation.
  • Multi-Session Reasoning — synthesize an answer scattered across many sessions.
  • Knowledge Updates — notice a fact changed and answer with the current one, not both.
  • Temporal Reasoning — reason about when things happened, not just what.
  • Abstention — know what it doesn't know, and say so instead of confabulating.

How it works

The LongMemEval paper frames every memory system as an indexing → retrieval → reading pipeline with four control points. greymemory implements the paper's recommended optimization at each one — and adds hybrid retrieval the paper's design doesn't have:

  • CP1 · Value — round-level chunk granularity (indexing).
  • CP2 · Key — fact-augmented chunk embeddings, K = V + fact (+9.4% recall).
  • CP3 · Query — LLM-extracted time-aware query expansion (+6.8–11.3% recall on temporal).
  • CP4 · Reading — Chain-of-Note + structured JSON answering (up to +10 points accuracy).

Contradictions are resolved at write time: an LLM classifier detects UPDATES / EXTENDS relationships, supersedes stale facts, and keeps full version history for time-travel queries, profiles, and derivations. Three memory types (fact · preference · episode); three edge types (UPDATES · EXTENDS · DERIVES).

96% of a funded cloud startup's accuracy — self-hosted, from SQLite, at $0.013 per session of ingestion. The story: on the categories where a memory engine actually matters (preference, temporal, multi-session) greymemory delivers +47, +28, +22 points of lift over just dumping the history into the context window.
